## 2. 识别文件类型并定位校验代码

附件是 42,857 字节的 i386 PE32 可执行文件，ImageBase 为 `0x00400000`。完整反汇编输出在 `analysis/checker_disassembly.txt`。初看字符串可以找到输入提示与成功/失败文本，再在反汇编中沿调用关系确认真正的判定逻辑：

### 2.1 `_main`：读入一行并调用校验器

`_main` 位于 VA `0x40152A`：

1. 打印输入提示。
2. 调用 `fgets`，栈上输入缓冲区地址为 `[esp+0x1e]`，第二个参数是 `0x32`（十进制 50），最多读 49 个输入字节并保留 C 字符串结尾。
3. 调用 `strcspn` 查找换行符，再将对应位置改成 `\0`。因此交互输入行末的回车/换行不会进入 flag 比较。
4. 把整理后的字符串传给 `_check_flag`。
5. 返回值为真则打印正确消息，否则打印错误消息。

候选长度为 43 字节，输入缓冲区容量足够。

### 2.2 `_check_flag`：变换输入后与常量比较

`_check_flag` 位于 `0x4014F0`：

1. 先调用 `_fake_check`。反汇编表明它只是输出干扰/提示文字并调用休眠函数；真正决定正确与否的是后续比较。
2. 把用户输入和局部输出缓冲区交给 `_encrypt_flag`。
3. 将固定地址 `0x404020` 作为第二个参数传给 `strcmp`，比较“变换后的输入”和程序内常量。
4. `strcmp` 返回 0 时，函数返回真。

因此题目的目标不是寻找隐藏文件或远程服务，而是恢复位于 `.data` 的比较常量，并逆转 `_encrypt_flag` 的简单变换。

### 2.3 `_encrypt_flag`：逐字节 XOR

`_encrypt_flag` 位于 `0x401490`。反汇编中的关键指令为：

```asm
401496: mov DWORD PTR [ebp-0x10],0x23   ; key = 0x23
4014b6: movzx ecx,BYTE PTR [edx]        ; input[i]
4014ba: mov edx,DWORD PTR [ebp-0x10]   ; key
4014bc: xor edx,ecx
4014be: mov BYTE PTR [eax],dl           ; output[i] = input[i] XOR key
```

循环计数从 0 开始；当 `i` 小于 `strlen(input)` 时继续。循环退出后在 `output[strlen(input)]` 写入 NUL。故每个有效字符满足：

\[
C_i = P_i \oplus 0x23
\]

其中 `P_i` 是用户输入字节，`C_i` 是与程序内常量比较的字节。异或具有自反性：

\[
P_i = C_i \oplus 0x23
\]

因此不用猜密钥，也不需要穷举；知道每个密文字节后，直接再 XOR 一次即可恢复明文。

## 3. 从 VA 映射到附件中的密文字节

`_check_flag` 将 `0x404020` 传给 `strcmp`，这是虚拟地址（VA），不是文件偏移。先根据 PE ImageBase 算 RVA，再根据 `.data` 节表把 RVA 换成原始文件偏移：

1. PE ImageBase：`0x00400000`。
2. 目标 RVA：`0x404020 - 0x400000 = 0x4020`。
3. `.data` 节的起始 RVA 为 `0x4000`，原始数据起始文件偏移为 `0x3200`。
4. 目标相对 `.data` 起始位置为 `0x4020 - 0x4000 = 0x20`。
5. 文件偏移：`0x3200 + 0x20 = 0x3220`。

由此从 `checker.exe` 的文件偏移 `0x3220` 开始读取，直到 NUL。密文长度为 43 字节，紧随其后的终止字节为 `00`。原始目标字节如下：

## 5. 正向复算与一致性检查

仅凭一次反解还可能出现偏移、节映射或抄录错误。这里做两层正向校验：

1. `analysis/solve_static.py` 从原 ZIP 和解压件读取数据，验证 ZIP 完整性、解压件字节相同、PE 头和节表有效，再由 `.data` 节映射得到文件偏移 `0x3220` 的 43 字节密文；将候选逐字节 XOR `0x23`，断言输出与目标密文完全一致。
2. `analysis/verify_forward.py` 使用单独的候选字面量重新执行正向变换，并断言候选长度为 43、`flag{...}` 格式成立、磁盘中的目标 43 字节逐字节相等，且双方 NUL 终止后的 C 字符串完全一致。
3. `analysis/root_verify_562.py` 由根代理独立解析 PE 头和节表，重新完成 VA→RVA→文件偏移换算并解密；输出 `FORWARD_XOR_EXACT=True`、`RESULT=PASS`。
4. `analysis/independent_audit_562_candidate.py` 由第二个子代理独立实现文件读取和 XOR 复算，得到相同候选及 `target match: True`。

该交叉校验能排除把 VA 当文件偏移、少读/多读一个字节、漏掉终止符以及 XOR 键抄错等常见错误。候选格式正确，43 字节密文全部参与比较，没有依赖字符串搜索猜出结果。
