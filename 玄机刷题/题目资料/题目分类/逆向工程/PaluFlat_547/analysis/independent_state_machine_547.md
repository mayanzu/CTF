## 固定 seed 下的实际路径

初始化字节位于 0x4015ae：C7 45 D8 39 30 00 00，即 seed=0x3039。该局部值在 0x401550 函数内没有其他写入；本次实际路径各次测试都针对这个固定值。

1. 状态0（0x4015e2）先比较当前下标和输入长度。seed bit 0 为 1，跳到 0x401654；seed bit 2 为 0，按输入下标奇偶选择 key，然后把状态设成 10（0x401689）。
2. 状态10（0x401a2a）再次按下标奇偶设置 key。seed bit 13 为 1，继续检查 bit 14；bit 14 为 0 时将状态设成 12（0x401a78）。
3. 状态12（0x401ade）取 input[i] 与 key[i mod 4] 异或，写入临时字节，然后设状态2（0x401ad2）。
4. 状态2（0x401785）执行按字节的移位/或。seed bits 6、7、8 均为 0，分支将状态设为3。
5. 状态3（0x401855）对临时字节减 0x55。seed bits 9、10、11 均为 0，分支将状态设为4。
6. 状态4（0x40191a）对临时字节取反，写入 output[i]，下标加一并回到状态0。

因此活跃路径为：0 → 10 → 12 → 2 → 3 → 4 → 0。state 2 的指令为 SHL/SAR/OR：Q(x)=((x<<4)&0xff) | ((int8(x)>>4)&0xff)。本候选的 XOR 结果都小于 0x80，所以 Q 在这些输入上等价于交换两个半字节；不能把 SAR 无条件简化成逻辑右移。

缓冲区 key 来自 0x401560 与 0x40156b 初始化的 C 字符串 palu 和 flat。状态0与状态10使用下标奇偶选择：偶数下标取 palu，下标 key 位置为 i mod 4；奇数下标取 flat，同样使用 i mod 4。

## 反推与逐字节正向校验

主函数 0x4020b4 起用 19 条立即数写入构造目标数组；0x402100 将要求长度设为 0x13。目标字节为：

f3 54 84 23 a4 74 d4 c3 30 5f 32 43 f0 54 f4 74 00 22 43

对每个目标 y，按活跃变换逆算：

- a = (~y) mod 256
- q = (a + 0x55) mod 256
- 由于所有 q 的低半字节都在 0..7，Q 的对应输入唯一：x = ((q & 0x0f) << 4) | (q >> 4)
- candidate[i] = x XOR key[i]

## 成功校验路径存在内在矛盾

主函数对转换结果调用 strlen，然后要求长度等于 19，之后才进行逐字节比较（0x402163–0x4021dd）。同一段代码的目标数组第 16 字节是 0x00。若转换输出匹配目标，第 16 字节必为 NUL，strlen 至多返回 16；若该字节非零，逐字节比较则会失败。故该二进制的成功条件不可满足。

反推值与正向密文字节一致，但它会在 strlen 门槛处被拒绝：输出第一个 NUL 在 offset 16，C 字符串长度是 16，目标长度是 19。这是附件内程序逻辑矛盾的证据；flag 候选可作为反推结果记录，不能据此声称程序校验已通过。

## 关键指令地址对照

以下指令地址与状态表目标地址交叉验证自只读反汇编记录 analysis/objdump_text.txt；独立脚本则直接从原 PE 的开头读取原始机器码和跳表，不依赖主 solver 的脚本。

- 0x4015b5–0x4015e0：状态上界检查以及基址相对跳表派发。指令序列比较 [rbp-4] 与 0x2d；取 [0x405000 + state*4] 的有符号 dword，符号扩展后加 0x405000，再间接跳转。
- 0x4015fe：seed bit 0 测试；bit 0 为 1 走到 0x401654。0x401654 测 bit 2；bit 2 为 0 时，0x401661–0x401686 按下标奇偶选择 palu/flat，然后 0x401689 写状态 10。
- 0x401a52：测试 seed bit 13。该 bit 为 1 时到 0x401a6b；0x401a6e 测 bit 14。bit 14 为 0 时，0x401a78 写状态 12。
- 0x401ade–0x401b07：从 input[i] 读取字节，以 i 除以 key 长度取余，读取 key[remainder]，异或并写到 [rbp-0x15]。0x401b04 的字节值与后续 seed 分支共同决定状态；seed bit 14 为 0，因此 0x401b14 直接写状态 2。需留意：本路径此前在状态10已经选好同样的 key。
- 0x401785–0x401797：临时字节的 SHL/SAR/OR 运算。候选路径 XOR 字节都小于 0x80，因此其效果是半字节交换。0x40179a 后检查 seed bits 6、7、8；均为 0，写状态 3。
- 0x401855–0x40188d：先减 0x55，再检查 seed bits 9、10、11；均为 0，写状态 4。
- 0x40191a–0x40193a：NOT 临时字节、写 output[i]、i 加一、状态清零，回到 dispatcher。
- 0x4020b4–0x4020ff：构造目标数组的 19 次 byte immediate store；第 16 项指令在 0x4020f4，立即数为 0x00。0x402100–0x402109 写入所需长度 0x13。
- 0x402163–0x40217d：调用 0x4036f0 后比较返回长度和 0x13。独立导入表解析确认 0x4036f0 的六字节 JMP thunk 指向 IAT 0x40937c，导入符号为 msvcrt.dll!strlen。然后 0x402195–0x4021d4 对 19 个字节逐一比较。
- main 的逐字节比较要求 output[16] 为零，而紧邻之前的 strlen 长度门槛要求返回 19。字符串长度门槛在这个目标上不可通过，因而实际成功分支不可达。
