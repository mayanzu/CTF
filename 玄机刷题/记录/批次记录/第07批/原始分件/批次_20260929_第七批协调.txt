### 反汇编并还原字符生成规则

objdump -d -C 可见 f(unsigned long long) 每次以 a=0、b=1 开始，循环 n 次执行 b=(a+b)&0xF、a=旧 b，最后返回查表串 K[a]。因此：

    f(n) = K[F_n mod 16]

其中 F_n 是斐波那契数列。模 16 的斐波那契数列周期为 24，所以先将大种子 n 化为 n mod 24，再索引对应的斐波那契模 16 值。

主函数在 i=0 到 31 共生成 32 个字符，初始 seed=1。每轮调用 f(seed) 取字符，然后更新：

    seed = (seed*8 + i + 64) mod 2^64

求解器逐项打印 i、seed、seed mod 24、F 值、K 索引和字符。例：i=0 时 seed=1，查表索引为 1，取字符 1；i=1 时 seed=72，72 mod 24=0，取 K[0]=0；i=2 时 seed=641，641 mod 24=17，F_17 mod 16=13，取 K[13]=6。

原始 32 字符串为 106326741d21909f2914769f60219a24。题目程序在字符下标 7、12、17、22 后显示连字符。第一次脚本逐次插入连字符，导致之前插入改变了后续索引，日志中出现了错误中间结果 flag{10632674-1d21-909f-2914-769f60219a24}。修正后从原始字符串一次性生成分组，得到：

    flag{10632674-1d219-09f29-14769-f60219a24}

该最终值提交玄机后返回 FLAG 正确，题目页显示“已完成”。截图仅在交互输出展示，没有保存为本地图片。

### 逐层复算证据

1. ABC literal-array 头部给出 21 个数组和索引表偏移 `0x6c`。索引 17 对应数组偏移 `0x265a`，与构造函数 `createarraywithbuffer` 对 `targetCipher` 的引用一致。数组声明 76 个 literal slots；每个字符串由 STRING tag 与 offset 两个槽组成，因此是 38 个字符串。脚本逐条检查 tag，保留顺序和重复项。
2. 将自定义 Base64 逆映射为标准 Base64 后，解码值是十进制 ASCII。比如 `ndG5nZa=` 解为 `48970`，`nte3ndK=` 解为 `51749`。38 项完整序列由脚本从 ABC 动态读取，没有写死在求解程序中。

4. 结合页面生命周期静态反汇编，构造函数的 `OHCTF2025` 是初始值；首次 `onPageShow` 在 `isInitialized == false` 时改为 `OHCTF2026` 并设为已初始化。因此页面检查实际使用 `OHCTF2026`。
5. KSA 根据字节码实现为 `j=(j+S[j]+key[j mod len]) mod 256`，随后交换 `S[i]` 与 `S[j]`。PRGA 产生的流字节与输入相加（模 256），故逆向是相减（模 256）。RSA 解出的中间字节经此逆变换得到候选 `flag{b80ebf0f0e210ad73664bdd19c16387e}`。

    seed = (seed*8 + i + 64) mod 2^64

求解器逐项打印 i、seed、seed mod 24、F 值、K 索引和字符。例：i=0 时 seed=1，查表索引为 1，取字符 1；i=1 时 seed=72，72 mod 24=0，取 K[0]=0；i=2 时 seed=641，641 mod 24=17，F_17 mod 16=13，取 K[13]=6。

原始 32 字符串为 106326741d21909f2914769f60219a24。题目程序在字符下标 7、12、17、22 后显示连字符。第一次脚本逐次插入连字符，导致之前插入改变了后续索引，日志中出现了错误中间结果 flag{10632674-1d21-909f-2914-769f60219a24}。修正后从原始字符串一次性生成分组，得到：

    flag{10632674-1d219-09f29-14769-f60219a24}

# 玄机题 #530：慕然回首，那人却在灯火阑珊处

## 结论

题目附件是一个 64 位 Windows 控制台迷宫程序。迷宫没有加密，直接以 10×10 字符数组保存在 PE 的 `.data` 段。按程序的方向定义从 `S` 走到 `E`，唯一的最短路为：

```text
ddddddssaaaaassdddssaa
```

按程序自己的提示格式推得候选 flag：

```text
flag{ddddddssaaaaassdddssaa}
```

**验证边界：** 静态代码确认程序到达 `E` 后会打印 `flag{your_path}` 格式提示并退出；它没有再读取或比较 flag。因此上面的值是由迷宫路径和提示格式推导出的候选 flag，不是程序内置比较器确认过的字符串。本分析未运行或加载 EXE，也未向平台提交。

## 迷宫数据与坐标

`objdump` 的 `.data` 转储在 VA `0x403040` 显示迷宫起始字节 `53 2a 2a 2a ...`，即 ASCII `S***...`。PE 映射关系将它定位到 RVA `0x3040`、文件偏移 `0x2640`。从这里连续读取的 100 字节只含 `S`、`E`、`*`、`#`，按程序的行宽 10 切分为：

```text
S******###
######*###
#******###
#*########
#****#####
####*#####
##E**#####
##########
##########
##########
```

在 `main` 中，当前行号保存在全局 `x`（VA `0x407030`），列号保存在 `y`（VA `0x407034`）。二者位于 `.bss`，初值为零；起点因此是 `(0,0)`。地址计算指令由 `x` 乘 10 再加 `y`，访问 `maze[x*10+y]`。终点 `E` 位于零起点坐标 `(6,2)`。

## 算法与控制流

`main` 首先在 `0x40153d`–`0x40155c` 打印欢迎语、方向说明和输入提示，然后在 `0x401561`–`0x40156f` 以格式串 `%c` 读取一个字符。格式串位于 VA `0x404079`；相关提示字符串位于 `.rdata`，偏移可在静态结果中查到。

控制流根据输入字符分支：`w`（`0x77`）上移、`a`（`0x61`）左移、`s`（`0x73`）下移、`d`（`0x64`）右移。每个分支先确认坐标不越界，再检查目标格是否为 `#`；仅当目标不是墙时才更新坐标。由此可还原为：

```text
while true:
    move = scanf("%c")
    if move == 'w' and x > 0 and maze[(x-1)*10+y] != '#': x -= 1
    elif move == 'a' and y > 0 and maze[x*10+(y-1)] != '#': y -= 1
    elif move == 's' and x <= 8 and maze[(x+1)*10+y] != '#': x += 1
    elif move == 'd' and y <= 8 and maze[x*10+(y+1)] != '#': y += 1
    elif move not in 'wasd':
        puts("Invalid move!")
        continue
    if maze[x*10+y] == 'E':
        puts("You are so clever! This is Jerry!")
        puts("xixi Now enter the flag in the format 'flag{your_path} ':")
        exit(0)
```

指令证据：方向比较在 `0x40157b`–`0x40159f`；四个移动分支读取并比较 `#` 后更新 `x` 或 `y`，大致位于 `0x4015a5`–`0x4016f3`；非法字符打印分支从 `0x4016f5` 开始；`0x401703`–`0x401735` 读取当前位置并比较 `E`；成功分支在 `0x401737`–`0x401754` 打印两条消息并调用 `exit(0)`。成功提示后没有下一次 `scanf`，也没有与 flag 常量进行比较。输入按 `%c` 每次消费一个字符；如果在抵达终点前读到换行，换行会落入非法字符分支。

## 路径求解与静态验证

将每个非墙格视作图节点，四邻接边分别标为 `w/a/s/d`，用 BFS 从 `S` 搜索到 `E`。`analysis/static_analyze.py` 同时统计最短路径数量并逐步模拟所得路径；结果是长度 22，最短路径数为 1，终点字符为 `E`。路线分段如下：

| 输入 | 到达坐标（行,列） | 说明 |
|---|---:|---|
| 起点 | `(0,0)` | `S` |

| `s×2` | `(2,6)` | 沿通道向下 |
| `a×5` | `(2,1)` | 第二条通道向左 |
| `s×2` | `(4,1)` | 沿左侧通道向下 |
| `d×3` | `(4,4)` | 向右到竖直通道 |
| `s×2` | `(6,4)` | 向下到末行 |
| `a×2` | `(6,2)` | 到达 `E` |

因此路径字符串为 `ddddddssaaaaassdddssaa`。每步都在边界内且目标格不是墙，末步落在 `E`。格式化后得到前述候选 `flag{ddddddssaaaaassdddssaa}`。

## 解密与验证说明、局限

这里没有需要逆向的加密算法：迷宫字符直接以 ASCII 明文存放在 `.data`，程序逻辑只执行移动、墙格过滤和终点判断。`analysis/static_analyze.py` 独立从 PE RVA 映射读取这些字节、按 10 列还原网格、用 BFS 求路，并静态模拟所有移动；这些检查验证了路径与二进制中迷宫及控制流的一致性。

## 1. 文件与证据

| `extracted/你好吗.exe`（也是 ZIP 唯一成员） | 132,122 bytes | `ACDFEF34BEBCBA03213C6CB270087ADD291B6692040A4854E8A2C007C42ADDF8` |

## 2. 代码与数据流

### 2.1 `main`：取出密文并拆成块

`main` 开头通过八条 `movabs rax, imm64` 把 ASCII 十六进制字符写入栈上字符串，顺序拼接后为 64 个字符：

```text
a897992e43bbec378107069c951bb75120d6353e369e0cea530408b6fa0975d2
```

接着它用 `strlen(hex) / 2` 得到 32 个字节，并以格式串 `%2hhx` 逐对解析成字节数组。十六进制数据解析在 `main` RVA `0x17af–0x17e7`；格式串位于 RVA `0x4000`。

随后 `main` 初始化四个 32 位密钥字：

```text
K[0] = 0x12345678
K[1] = 0x87654321
K[2] = 0xabcdef98
K[3] = 0x98fedcba
```

循环每次前进 8 字节，调用 `sub_101`，所以 32 字节密文被分为四个独立的 8 字节块。块内两个 32 位字按 x86-64 小端序读写。

### 2.2 `sub_101`：TEA 解密

反汇编可见 `sub_101` 先读取输入块的两个 `unsigned int`，设置初始 sum 为 `0xC6EF3720`、delta 为 `0x9E3779B9`，并将循环计数从 0 增加到 31（共 32 次）。代码对 v1、v0 依次执行减法；加法、减法均按 32 位无符号算术回绕：

```text
sum = 0xC6EF3720                   # (0x9E3779B9 * 32) mod 2^32
repeat 32 times:
    v1 -= (((v0 << 4) + K[2]) ^ (v0 + sum) ^ ((v0 >> 5) + K[3]))
    v0 -= (((v1 << 4) + K[0]) ^ (v1 + sum) ^ ((v1 >> 5) + K[1]))
    sum -= 0x9E3779B9
```

这是固定四个密钥下的标准 TEA 反向轮函数（不是 XTEA 的按 sum 索引密钥形式）。指令证据包括函数内对两个块字的加载、立即数 `0xC6EF3720`/`0x9E3779B9`、位移 4 和 5、XOR、两次 dword 减法，以及计数器与 `0x1f` 比较后走 `jbe` 回边。反向顺序是先更新 v1，再更新 v0。

### 2.3 `sub_102`：按末字节截断

`sub_102` 调用 `strlen`，取字符串最后一字节，并用 `movsx` 将其作为有符号 `char` 扩展。然后在 `buf[strlen(buf) - last]` 写入 NUL。这相当于信任末字节指定的填充长度；函数没有逐字节验证填充内容。

本题解密后末尾恰好有六个 `0x06`，因此截断位置是 `32 - 6 = 26`。本例长度为正且在缓冲区内，不触及该截断函数对负值或异常填充值的脆弱边界。

### 2.4 `sub_100`：最后的单字节 XOR

`main` 向 `sub_100` 传入 `0x16`。该函数遍历当前 C 字符串长度，对每个字节原地执行 `buf[i] ^= 0x16`。注意 `0x16` 在 `main` 中先写入 `[rbp+4]` 局部变量，再重新加载作为第二参数；因此应从栈局部赋值而非假设立即数直接进入参数寄存器来识别它。

## 3. 解密、截断与验证

将 64 位十六进制字符串解析后，密文字节为：

```text
a8 97 99 2e 43 bb ec 37 81 07 06 9c 95 1b b7 51
20 d6 35 3e 36 9e 0c ea 53 04 08 b6 fa 09 75 d2
```

按上述 32 轮 TEA 解密四块，得到 32 字节：

```text
hex:  70 7a 77 71 6d 2f 73 21 20 73 23 21 74 3b 77 2f
      24 27 3b 22 75 74 75 3b 2e 6b 06 06 06 06 06 06
text: pzwqm/s! s#!t;w/$';"utu;.k + 六个 0x06
```

`sub_102` 取末字节 `0x06`，将 NUL 写到偏移 `26`，留下 26 字节：

```text
pzwqm/s! s#!t;w/$';"utu;.k
```

之后对这 26 字节逐字节 XOR `0x16`：

```text
flag{9e76e57b-a921-4cbc-8}
```

验证时将 TEA 加密函数按正向轮序作用于解密出的四个块，并使用相同密钥、delta 和轮数；脚本检查重新生成的 32 字节与原始密文完全一致。这确认了块端序、密钥、轮数和 TEA 轮次方向。输出串长度为 26，末段只有一个字符 `8`；它虽不像常见 UUID 分组长度，但这是字节级按程序逻辑得到的结果，未擅自补字或改格式。
